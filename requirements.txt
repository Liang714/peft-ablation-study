# Core ML stack.

# torch is deliberately left loose (not pinned exactly): on Colab it's
# already preinstalled matched to that session's specific GPU/CUDA driver,
# and force-pinning a different version here risks pip installing a
# mismatched build and silently breaking torch.cuda.is_available(). Every
# other package below IS pinned exactly, after three separate Colab-only
# bugs (DataCollatorForSeq2Seq behavior, a deprecation warning, and a
# tokenizer-loading crash) all turned out to be the same root cause: this
# file had no upper bounds, so Colab installed newer versions than what was
# actually tested locally. These exact pins are the locally-validated
# versions (confirmed working together, incl. a real GPU-free training +
# eval dry-run) — if you bump one, re-run the local dry-run before trusting
# it on Colab.

transformers==4.57.6

# bitsandbytes (NF4 quantization for QLoRA) is intentionally NOT here — it's CUDA-only and has no
# macOS wheels at all beyond 0.42.0, so including it here would make `pip install -r
# requirements.txt` fail immediately (and install nothing) on this Mac or any non-CUDA machine.
# See requirements-gpu.txt — installed as an extra step, only needed for configs/qlora.yaml,
# only on a real CUDA machine (Colab/Kaggle).

# NOTE: mlflow (requirements-tracking.txt — MUST be installed first, as its own separate

# a version choice here can dodge. pyarrow==21.0.0 (favoring datasets, installed second/last so
# it wins) verified working for both libraries' actual functionality via a smoke test; pip will
# still print a conflict warning mentioning mlflow when this installs, which is safe to ignore.
